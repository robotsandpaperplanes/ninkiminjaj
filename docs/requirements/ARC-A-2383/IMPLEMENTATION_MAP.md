# DEV-126326 implementation map

## Scope and baseline

The [product story](../../reference/ARC-A-2383/ARC-A-2383.pdf) is the behavioral authority (BRs on pp. 6–12, ACs on pp. 12–17, open questions on pp. 21–22). The five [HTML references](../../reference/ARC-A-2383/) inform layout and interaction. The [integration reference](../../INTEGRATION.md) documents the current prototype. Findings are based on static inspection of active source and related test definitions.

**Implemented** means the requirement is present in the active prototype. **Partially Implemented** means a relevant subset runs, often limited to the existing DEV-119436 simulations. **Missing** means the target path is absent and prototype work can start after approval. **Blocked** means the required outcome is absent and needs an unresolved technical or product contract. A simulated result does not establish production readiness.

## Priorities and implementation order

1. **P0 — Confirm contracts and preserve the baseline.** Resolve the critical questions P-2/P-4/P-5/P-8 with the responsible teams. Confirm topology and capability sources (P-1/P-3/P-7), shipped product workflows (P-6) and the legacy General operations. Use existing route, On-Prem model and render checks as the regression baseline.
2. **P1 — Add the Server area navigation and inventory model.** Keep the Cloud shell, theme, Russian UI copy, header mode switch, direct routes and General workflows. Add synthetic full/reduced/outage examples, and distinguish installed, unavailable and unsupported capabilities. Connect single entry and fault boundaries when P-4/P-5 are resolved.
3. **P1 — Add Meetings media and Meetings/Chats flags.** Build with existing forms, dialogs and status components. Verify no-op and invalid requests, per-target readback and scoped history. Use clearly identified synthetic data until confirmed service contracts are available.
4. **P1 — Implement solution lifecycle.** Start with scope, dependency preview, confirmation, history and resume by ID. Integrate execution after P-1–P-3/P-5. Verify blocked shared-service shutdown, partial or unknown results, post-maintenance application readiness and the separate external VM bootstrap path.
5. **P1 — Add diagnostics views, then package export.** Build the read-only views first. Verify partial collection, typed probes, expected Compose containers and read-only filesystems after P-7. Ship the separate package workflow after P-8, with successful VM files retained in partial cases and external viewer acceptance.
6. **P2 — Integrate existing product administration.** Wire owner-approved Disk, Mail and Boards workflows after P-4–P-6. Verify shipped permissions, audit, and operation parity. Run final regression checks on Cloud/Server routes and existing General actions.

Implementation awaits approval. No application behavior was changed or runtime validation performed in this audit.
